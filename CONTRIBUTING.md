# Contributing

Use a feature branch (`docs/*`, `feature/*`, `infra/*`, `security/*`, `fix/*`) and a pull request into `main`. Do not commit directly to `main`. Include scope, tests, security impact, documentation and checklist references in every PR. Record consequential architecture decisions in `docs/adr/`. Avoid committing credentials, secrets or tokens. Changes touching auth, permissions or bootstrap require negative security tests and explicit review before merging.
